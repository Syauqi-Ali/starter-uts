## 1. Daftar tugas dan UI responsif. Lengkapi halaman daftar agar menampilkan judul tugas, mata kuliah, status selesai/belum selesai, dan ringkasan jumlah tugas. Tampilkan empty state bila belum ada data. Pada lebar 360 px gunakan layout yang tidak overflow; pada lebar 700 px atau lebih tampilkan kartu dalam dua kolom.
- Jawaban: Pada bagian ini, antarmuka daftar tugas dirancang informatif dan responsif dengan menampilkan ringkasan jumlah tugas serta kartu berisi judul, mata kuliah, dan status selesai, dilengkapi empty state saat data kosong, yang memanfaatkan LayoutBuilder untuk menampilkan tata letak satu kolom tanpa overflow pada layar 360 px dan bertransformasi otomatis menjadi dua kolom pada layar 700 px ke atas, di mana kendala overflow sebelumnya berhasil diatasi menggunakan widget Expanded dan penyesuaian mainAxisExtent pada GridView.

## 2. Form, validasi, dan navigasi. Lengkapi form tambah tugas dan halaman detail. Judul dan mata kuliah wajib diisi setelah spasi di awal/akhir dibuang. Buka halaman menggunakan Navigator.push. Saat Simpan, kembalikan Task ke halaman daftar dengan Navigator.pop; saat Batal, kembali tanpa mengubah daftar.
- Jawaban: Pada bagian ini, form penambahan tugas dilengkapi dengan validasi input yang memastikan judul dan mata kuliah wajib diisi setelah spasi di awal dan akhir dibuang menggunakan `.trim()`. Navigasi pembukaan halaman menggunakan `Navigator.push`, sedangkan saat menekan tombol Simpan, objek `Task` dikembalikan ke halaman daftar dengan `Navigator.pop(context, task)` setelah form berhasil divalidasi. Ketika tombol Batal ditekan, halaman ditutup menggunakan `Navigator.pop(context)` tanpa melakukan perubahan pada daftar tugas.

## 3. State dan interaksi daftar. Pastikan tugas baru langsung muncul pada daftar. Sediakan aksi untuk menandai tugas selesai atau belum selesai. Perubahan status harus langsung terlihat pada kartu dan ringkasan jumlah tugas.
- Jawaban: Pada bagian ini, pengelolaan *state* menggunakan `setState` memastikan tugas baru yang diterima dari hasil `Navigator.push` langsung ditambahkan ke dalam daftar `_tasks` dan muncul pada antarmuka[1]. Aksi menandai tugas selesai atau belum selesai ditangani melalui fungsi `_toggleTask` yang mengubah status `isDone` pada objek tugas terkait. Pembaruan *state* ini secara otomatis memperbarui tampilan UI, sehingga status baru langsung terlihat pada kartu tugas (`TaskCard`) serta memperbarui perhitungan tugas selesai dan belum selesai pada widget ringkasan (`_SummaryCard`) secara *real-time*.

## 4. Operasi asynchronous dan state UI. Muat daftar melalui operasi asynchronous. Tampilkan indikator loading selama proses; setelah selesai, tampilkan empty state atau daftar data. Jika pembacaan gagal, tampilkan pesan error yang mudah dipahami dan tombol Coba Lagi. Gunakan kontrol simulasi yang tersedia pada starter untuk menguji kondisi error.
- Jawaban: Pada bagian ini, pemuatan daftar tugas dilakukan secara *asynchronous* melalui fungsi `_loadTasks` yang memanggil `_storage.load()`. Selama proses berlangsung, status `_isLoading` bernilai `true` dan UI menampilkan indikator pemuatan `CircularProgressIndicator`[1]. Setelah selesai, UI secara dinamis menampilkan *empty state* jika tidak ada data atau *grid* kartu tugas jika data tersedia. Jika pembacaan gagal, penanganan *exception* akan mengisi `_errorMessage` dengan pesan kesalahan yang mudah dipahami serta menampilkan tombol "Coba lagi" untuk memicu pemuatan ulang. Pengujian kondisi error didukung oleh opsi "Simulasikan error saat memuat" pada menu *popup* `AppBar` yang memicu variabel simulasi `_simulateNextError`.

## 5. Penyimpanan lokal dan verifikasi. Simpan daftar menggunakan SharedPreferences dalam bentuk JSON. Baca kembali data saat aplikasi dimulai, termasuk status setiap tugas. Uji tambah tugas, ubah status, tutup dan jalankan ulang aplikasi. Jalankan pada ukuran telepon dan tablet serta flutter analyze. Siapkan berkas pengumpulan sesuai instruksi.
- Jawaban: Pada bagian ini, penyimpanan data dilakukan melalui kelas `TaskStorage` dengan mengubah daftar objek `Task` menjadi string berformat JSON menggunakan `jsonEncode` dan menyimpannya ke `SharedPreferences` menggunakan fungsi `setString`. Saat aplikasi dimulai, fungsi `load()` membaca string JSON dari `SharedPreferences`, mengunduhnya kembali dengan `jsonDecode`, serta mengonversi setiap elemen menjadi objek `Task` melalui `Task.fromJson`, sehingga seluruh daftar beserta status `isDone` dapat dipulihkan secara utuh. Pengujian verifikasi dilakukan dengan menambah tugas baru dan mengubah statusnya untuk memastikan perubahan tersimpan permanen saat aplikasi ditutup dan dibuka kembali. Terakhir, antarmuka diuji pada ukuran layar telepon dan tablet serta dipastikan bebas dari kesalahan linting dengan menjalankan perintah `flutter analyze` sebelum penyiapan berkas pengumpulan.
